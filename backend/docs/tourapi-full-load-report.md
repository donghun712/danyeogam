# 전국 TourAPI 스탬프 카탈로그 적재 결과

검증일은 2026-09-07이며, 기존 사용자 DB와 분리한 MySQL 8.0.44 임시 인스턴스에서 실행했다.

## 최종 서비스 범위

다녀감의 핵심 목적을 주변 문화·역사 관광지 방문과 스탬프 획득으로 한정했다. TourAPI 전체 유형을 서비스하지 않고 다음 두 유형만 저장한다.

| 포함 유형 | contentTypeId | 건수 |
|---|---:|---:|
| 관광지 | 12 | 12,614 |
| 문화시설 | 14 | 2,721 |
| 합계 |  | 15,335 |

향후 동기화도 `areaBasedList2` 호출 시 `contentTypeId=12`, `contentTypeId=14`를 각각 전달한다. 따라서 제외 유형은 원본 staging 단계부터 새로 유입되지 않는다.

## 초기 검증에서 제외된 1,055건

| 사유 | 건수 | 처리 |
|---|---:|---|

| 주소 좌표 검색 결과 없음 | 20 | TourAPI 좌표가 없고 카카오 주소 검색으로도 확정 불가 |
| 대한민국 허용 범위 밖 좌표 | 18 | 잘못된 위치가 GPS 스탬프 대상이 되지 않도록 차단 |

## 초기 덤프의 필드 범위

허용 유형의 이름, 주소, 유형, 지역, 좌표, 전화번호, 수정 시각과 대표 원본·썸네일 이미지를 적재했다. 관광지별 `detailCommon2` 설명과 `detailImage2` 추가 이미지의 전국 일괄 수집은 개발키 호출량을 보호하기 위해 아직 실행하지 않았다. 상세 조회 API는 설명이 없을 때 `null`, 추가 사진이 없을 때 대표 이미지 또는 빈 배열을 안전하게 반환한다.

## 복원 검증

빈 DB에 Flyway V1을 적용한 뒤 `db/danyeogam_tour_seed.sql`을 복원하고 백엔드를 재기동했다. 지역 284건, 장소 15,335건, Flyway 성공 이력 1건, `sx_tourist_spot_location` 공간 인덱스 1개를 확인했다. SQL 덤프에는 TourAPI·카카오 키가 포함되지 않는다.
