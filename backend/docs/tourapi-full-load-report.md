# 전국 TourAPI 스탬프 카탈로그 적재 결과

검증일은 2026-09-08이며, MySQL 8.0.44와 실제 `KorService2` 응답을 사용했다.

## 최종 서비스 범위

다녀감의 핵심 목적을 역사·문화 장소 방문과 스탬프 획득으로 한정했다. `contentTypeId`만으로 관광지와 문화시설 전체를 허용하지 않고 `lclsSystm1/2/3` 세부 분류까지 함께 적용한다.

| 포함 기준 | 실제 활성 건수 |
|---|---:|
| 역사유적 `HS01` | 2,376 |
| 역사유물 `HS02` | 398 |
| 박물관 `VE070100` | 594 |
| 기념관 `VE070200` | 155 |
| 미술관·화랑 `VE070600` | 362 |
| 합계 | 3,885 |

실제 API의 선정 후보는 3,887건이었다. 아래 2건은 유효 좌표를 확보하지 못해 스탬프 대상에 승격하지 않았다.

| contentId | 이름 | 분류 | 처리 결과 |
|---|---|---|---|
| `125793` | 만경대 | `HS01/HS011200` | TourAPI 좌표 없음, 카카오 주소 검색 결과 없음 |
| `2649844` | 서해수호관 | `VE070100` | TourAPI 좌표 없음, 카카오 주소 검색 결과 없음 |

## 제외 정책

- 종교성지 `HS03`, 안보관광지 `HS04`는 포함하지 않는다.
- 랜드마크·자연·체험 등 `HS01`, `HS02`가 아닌 관광지는 포함하지 않는다.
- 문화시설은 박물관, 기념관, 미술관·화랑만 포함한다.
- 행사·축제, 여행코스, 레포츠, 숙박, 쇼핑, 음식점은 포함하지 않는다.

기존 활성 카탈로그 15,335건 중 새 기준 밖의 11,450건은 삭제하지 않고 `active=false`, `spot_type=GENERAL`, `stamp_enabled=false`, `stamp_radius_meters=null`로 전환했다. 선정 기준을 다시 조정할 때 원본 행을 복구하거나 재동기화할 수 있다.

분류 컬럼은 Flyway `V2__add_tour_classification.sql`로 추가했다. 전국 동기화가 모든 선정 조건의 전체 페이지를 읽은 경우에만 비선정 행을 비활성화한다. 지역 한정 또는 페이지 제한 실행은 기존 전국 카탈로그를 건드리지 않는다.

## 현재 덤프의 필드 범위

선정 장소의 이름, 주소, 유형, 세부 분류, 지역, 좌표, 전화번호, 수정 시각과 대표 원본·썸네일 이미지를 저장한다. 2026-09-13에는 관광지별 `detailCommon2`, `detailIntro2`, `detailImage2` 증분 수집을 완료했다. 활성 관광지 3,885건 모두 공통 상세·소개정보 호출 완료 시각이 있고, 상세 설명 3,885건과 상세 이미지 25,835건을 저장했다. 운영시간·휴무일이 비어 있는 장소는 TourAPI 원본에서 값을 제공하지 않은 경우다.

## 복원 데이터

`db/danyeogam_tour_seed.sql`은 활성 지역, 활성 스탬프 대상 3,885건, 해당 상세 이미지와 지역 칭호 정의만 포함하도록 생성한다. API 키, 익명 세션, 방문, GPS 인증 시도, 즐겨찾기, 칭호 획득, staging, 동기화 이력은 포함하지 않는다. 복원 전 백엔드를 한 번 실행해 Flyway V1~V6를 먼저 적용해야 한다.
