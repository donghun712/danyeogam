# Codex에게 붙여넣을 프롬프트 — 즐겨찾기 기능

다녀감 백엔드(danyeogam) 저장소에서 작업을 진행해줘.

## 배경

화면시안 관광지 상세에 ♡좋아요 / ⧉공유(이미 프론트에서 구현 완료) / ⭐즐겨찾기 아이콘
3개가 있어. 공유는 순수 프론트 기능(Web Share API)이라 이미 만들었고, 이번엔 즐겨찾기를
요청해.

## 결정 필요 — 먼저 확인해줘

시안엔 "좋아요"와 "즐겨찾기"가 별개 아이콘으로 있는데, 이 둘을 각각 다른 기능(좋아요=전체
사용자 집계 카운트, 즐겨찾기=내 저장 목록)으로 만들지, 아니면 하나로 합칠지 확정이 안 됐어.

**내 제안(이견 없으면 이대로 진행)**: 두 개를 합쳐서 "즐겨찾기" 하나만 만들어줘. 전체
사용자 좋아요 카운트 같은 집계 기능은 이 서비스(개인 스탬프 수집 앱) 성격상 지금 당장 큰
가치가 없어 보여. 만약 정말 둘을 분리하고 싶으면, 코드 짜기 전에 나한테 먼저 확인해줘.

## 조건

- 기존 세션 구조(`dg_session` 쿠키, `POST /sessions/anonymous`)를 그대로 재사용해줘.
  즐겨찾기도 스탬프/도감처럼 익명 Actor 기준으로 저장하면 될 것 같아.
- 새 인증 방식이나 회원 시스템을 만들지 마 — 지금 있는 익명 세션 구조 안에서 처리해줘.
- 아래는 제안일 뿐이고, 프로젝트 기존 코드 스타일(패키지 구조, 네이밍)에 맞게 조정해서
  구현해줘.

```
POST   /api/v1/tourist-spots/{id}/favorite     — 즐겨찾기 추가
DELETE /api/v1/tourist-spots/{id}/favorite     — 즐겨찾기 해제
GET    /api/v1/me/favorites                    — 내 즐겨찾기 목록
```

`GET /api/v1/tourist-spots/{id}` 상세 응답에도 `favorited: boolean` 필드를 추가해줘 —
프론트가 상세 화면을 열 때마다 즐겨찾기 여부를 바로 알 수 있어야 아이콘 상태(채워짐/빈
별)를 표시할 수 있어.

`GET /api/v1/me/favorites`는 도감처럼 관광지 카드에 필요한 최소 정보만 내려주면 돼
(`touristSpotId`, `name`, `thumbnailUrl`, `visitState` 정도. 정확한 필드 구성은 기존
`GET /me/collection` 응답 구조 참고해서 비슷하게 맞춰줘).

- 중복 요청(이미 즐겨찾기 상태에서 다시 POST) 처리 방식은 알아서 판단해도 좋아(에러를 내든,
  멱등하게 처리하든) — 다만 어떻게 했는지 보고해줘.
- 기존 API(`TouristSpotDetailResponse` 등)의 다른 필드는 그대로 유지해줘.
- Swagger(`docs/openapi.yaml`)와 `docs/frontend-read-api.md`를 갱신해줘. 즐겨찾기 API는
  새 문서(`docs/frontend-favorites-api.md` 같은 이름)로 만들어도 좋아.

## 확인해야 할 것

1. 기존 테스트가 깨지지 않는지
2. 실제로 추가 → 조회 → 삭제 흐름이 되는지
3. 세션이 없는 상태에서 호출하면 어떻게 되는지(다른 API처럼 `AUTHENTICATION_REQUIRED`로
   통일해줘)

## 보고 형식

1. 결정한 사항(좋아요/즐겨찾기 통합 여부)과 이유
2. 변경/추가한 파일 목록
3. 최종 API 스펙 (경로, method, request/response)
4. 테스트 결과
5. 실제 응답 예시 (추가 → 조회 → 삭제 각 단계)

프론트엔드 코드는 건드리지 마 (별도 저장소). 애매한 부분이 있으면 임의로 넘기지 말고 먼저
알려줘.
